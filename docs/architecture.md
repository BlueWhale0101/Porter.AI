# Porter.AI architecture — V0 with V1 Knowledge foundation

Porter owns the Travel domain, independently of Assistant.AI and Coach.AI. Its only authoritative concepts are **Trip**, **Event**, and **Knowledge**. A Trip owns its Events and lightweight semantic participants; Knowledge belongs directly to the authenticated owner and may be referenced through non-owning Event/Trip context associations; participants are never authentication users in V0.

Events remain generic. `movement`, `accommodation`, and `hire` are the only special-handling fields: each changes deterministic projection behavior. `optional` Events are useful planning source truth but never compete as operational Now/Next. Booking, access expectations, artifacts, temporal/spatial expressions, provenance, and visual data are Event aspects. An artifact names the expected-admission IDs it satisfies (`satisfiesAdmissionIds`), rather than relying on participant overlap. Artifact metadata contains an opaque storage reference; `ArtifactStorage` is the provider boundary, so Supabase Storage paths never leak into domain or projection code. Original artifacts remain authoritative; derived QR/barcode data is explicitly derivative metadata.

Knowledge is sparse contextual truth. Its plural context fields are JSON arrays and validity is a paired range object. Parking is projected only from current parking-tagged Knowledge; Porter never infers it from movement or tracking.

Source tables are `travel_trips`, `travel_events`, and `travel_knowledge`. Source truth is mutable with optimistic revisions but stable IDs, owner/Trip identity as applicable, and creation timestamps are immutable. The runtime path is **MCP → semantic `PersistentPorterService` → persistence adapter → Supabase source truth → deterministic TripPacket**. Row mappers are the only place database snake_case enters Porter. `TripPacket` is a deterministic, read-only projection: source structure establishes leaves before perspective filters visibility, and children whose parent is not visible are rooted safely. Leaf Events drive Past/Now/Next/Later. Active accommodation/hire resources promote Knowledge explicitly associated through `relatedEventIds`. Assistant may orchestrate Gmail/Calendar and Porter together, but Porter does not ingest Gmail or Calendar itself; MCP callers use semantic operations rather than tables or SQL.

V1 global Knowledge foundation and the staged production rollout/rollback boundaries are described in [global-knowledge-foundation.md](global-knowledge-foundation.md). No library UI or selective synchronization is included in that phase.
